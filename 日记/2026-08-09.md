# 分析：改造后的 ArtTitle 组件失去蜡笔纹理及描边效果的原因

经过对比两个组件的代码，我找到了**根因**：`lightenHsl` 函数的返回值与 `builtInPresets` 中对它的使用方式存在冲突，导致所有内置预设的 `lightColor`（渐变浅色）生成了**无效的 CSS 颜色值**，进而破坏了 SVG 渐变定义。

---

## 根因详解

### 问题链路

**第 1 步**：`lightenHsl` 函数返回**已经包裹了 `hsl()` 的完整字符串**：

```typescript
// ArtTitle.vue 第 222-227 行
const lightenHsl = (hsl: string, amount: number): string => {
  if (!hsl) return '#ffffff'
  const parts = hsl.split(' ')
  if (parts.length !== 3) return hsl
  return `hsl(${parts[0]} ${parts[1]} ${Math.min(100, parseFloat(parts[2]) + amount)}%)`
  //     ^^^^ 已经包裹了 hsl()
}
```

**第 2 步**：`initPresets` 中又将返回值**再次包裹了一层 `hsl()`**：

```typescript
// ArtTitle.vue 第 233 行（以 pink 为例）
lightColor: `hsl(${lightenHsl(pink, 10) || '330 80% 65%'})`,
//           ^^^^ 又包了一层！→ 双重包裹
```

**第 3 步**：产生的实际颜色值变为**无效字符串**：

| 场景 | `lightenHsl` 返回值 | 最终 `lightColor` | 是否有效 |
|------|---------------------|-------------------|----------|
| CSS 变量已定义（如 `pink = '330 80% 55%'`） | `hsl(330 80% 65%)` | `hsl(hsl(330 80% 65%))` | ❌ 双重包裹 |
| CSS 变量未定义（`pink = ''`） | `#ffffff` | `hsl(#ffffff)` | ❌ 无效格式 |

**第 4 步**：无效的 `lightColor` 被用于 SVG 渐变的第一个 `<stop>`：

```html
<linearGradient :id="cfg.id" x1="0%" y1="0%" x2="100%" y2="100%">
  <stop offset="0%" :stop-color="cfg.lightColor" />  <!-- ← 无效！如 hsl(hsl(...)) -->
  <stop offset="100%" :stop-color="cfg.color" />      <!-- ← 有效 -->
</linearGradient>
```

浏览器遇到无效的 `stop-color` 时，会忽略该渐变停止点或整个渐变定义，导致文字填充（`fill`）失效。

### 为什么 `color` 和 `shadowColor` 没问题？

```typescript
// color — 只包裹一次，始终有效
color: `hsl(${pink || '330 80% 55%'})`,        // → hsl(330 80% 55%) ✅

// shadowColor — 只包裹一次，始终有效
shadowColor: `hsl(${getCssVar('--brand-pink-shadow') || '330 50% 30%'})`,  // ✅

// lightColor — 双重包裹！
lightColor: `hsl(${lightenHsl(pink, 10) || '330 80% 65%'})`,  // ❌
```

所以**描边（stroke）本身的值是有效的**，但因为渐变填充失效，文字整体渲染异常，视觉上看起来像是"蜡笔纹理和描边效果都丢失了"。

---

## 修复方案

修改 `lightenHsl` 函数，使其**返回不包裹 `hsl()` 的纯 HSL 值**（与 `getCssVar` 的返回值格式保持一致），让 `initPresets` 中的外层 `hsl()` 成为唯一的包裹层

---

## 修复说明

改动只有一处：[lightenHsl 函数](file:///d:/personal%20project/remnant-song-web/src/components/common/ArtTitle.vue#L222-L227)，两个变化：

1. **去掉 `hsl()` 包裹**：`return \`hsl(...)\`` → `return \`...\``（只返回纯 HSL 数值）
2. **空值回退改为空串**：`return '#ffffff'` → `return ''`（让 `initPresets` 中的 `||` 回退值 `'330 80% 65%'` 等生效）

修复后，`initPresets` 中的生成逻辑保持不变：
```typescript
lightColor: `hsl(${lightenHsl(pink, 10) || '330 80% 65%'})`,
```
现在 `lightenHsl` 返回 `'330 80% 65%'`（纯数值），外层 `hsl()` 包裹一次 → `hsl(330 80% 65%)` ✅ 有效。

---

### 补充：原组件为什么没问题？

原组件 `ArtTitle_original.vue` 的 `color` 函数内部已经正确处理了包裹逻辑，它始终自己包一层 `hsl()`，不存在"函数内包一层 + 调用方再包一层"的双重包裹问题：

```typescript
// 原组件 — 一层包裹，始终正确
const color = (varName, lightAdd = 0) => computed(() => {
  const base = getHslValue(varName)
  return `hsl(${base})`  // 或 lightAdd > 0 时: `hsl(${parts[0]} ${parts[1]} ${newL}%)`
})
```

改造后的组件将"读取 CSS 变量"和"提亮计算"拆成了两个函数（`getCssVar` + `lightenHsl`），但 `lightenHsl` 错误地复刻了原组件中"自己包裹 `hsl()`"的行为，而 `initPresets` 中又额外包了一层，导致双重包裹。

## 根因：`shadowColor` 全部生成无效颜色

改造后的 `initPresets()` 对 `shadowColor` 的处理存在**两种相反的格式错误**：

### 错误 1：pink / purple / orange / cyan — 把 HEX 颜色塞进了 `hsl()`

```typescript
// CSS 变量是 HEX 颜色：#B5447B
shadowColor: `hsl(${getCssVar('--brand-pink-shadow') || '330 50% 30%'})`
// → hsl(#B5447B)  ❌ 无效！hsl() 不接受 HEX 参数
```

### 错误 2：muted — 纯 HSL 数值没有包裹 `hsl()`

```typescript
// CSS 变量是纯数值：240 6% 30%
shadowColor: mutedFg || '#333333'
// → 240 6% 30%  ❌ 无效！缺少 hsl() 包裹
```

**所有 5 个预设的 `shadowColor` 全部无效**，因此 SVG 的 `stroke` 属性收到无效颜色值，浏览器直接忽略，描边完全消失。

---

## 修复总结

| 预设 | CSS 变量实际值 | 修复前（无效） | 修复后（有效） |
|------|---------------|---------------|---------------|
| pink | `#B5447B` | `hsl(#B5447B)` ❌ | `#B5447B` ✅ |
| purple | `#3C3D4F` | `hsl(#3C3D4F)` ❌ | `#3C3D4F` ✅ |
| orange | `#873706` | `hsl(#873706)` ❌ | `#873706` ✅ |
| cyan | `#2B3E44` | `hsl(#2B3E44)` ❌ | `#2B3E44` ✅ |
| muted | `240 6% 30%` | `240 6% 30%` ❌ | `hsl(240 6% 30%)` ✅ |

核心改动：**pink/purple/orange/cyan 的 shadow 是 HEX 颜色，直接使用，不再强制包裹 `hsl()`；muted 的 shadow 是纯 HSL 数值，用 `hsl()` 包裹。**
