## 分析结论

先把结论说清楚：**部署到 Vercel 后，当前架构下会有同样的问题**。原因不在于 Vercel，而在于你的 API 调用发生在哪里。

---

### 当前架构 → 问题所在

你现在的代码是纯客户端 SPA，GitHub API 调用全部发生在**用户浏览器**中：

```
用户浏览器（中国）──→ api.github.com          ❌ 被墙/不稳定
用户浏览器（中国）──→ raw.githubusercontent.com ❌ 被墙/不稳定
```

Vercel 部署只是把你的静态文件（HTML/JS/CSS）托管到了全球 CDN，但 JS 代码仍然在用户浏览器里执行，`fetch()` 请求仍然从用户的网络发出。**把静态文件搬到 Vercel 上，并不改变 API 请求的源头。**

所以问题分两层：

| 层面                 | 现状       | Vercel 部署后             |
| ------------------ | -------- | ---------------------- |
| 访问你的网站（vercel.app） | N/A      | 国内可能慢/不稳定，绑自定义域名可改善    |
| 浏览器调用 GitHub API   | ❌ 需要 VPN | ❌ 仍然需要 VPN（请求源仍是用户浏览器） |

---

### 解决方案（按推荐度排序）

#### 方案一：Vercel Serverless Functions 做代理（推荐 ⭐）

把 GitHub API 调用从客户端搬到 Vercel 服务端，浏览器只和你的 Vercel Function 通信：

```
用户浏览器（中国）──→ your-site.vercel.app/api/posts  ✅ 通过 Vercel CDN
                                        │
                          Vercel Serverless Function（美国/AWS）
                                        │
                                        └──→ api.github.com  ✅ 服务器直连无墙
                                        └──→ raw.githubusercontent.com  ✅ 同上
```

**优点**：用户体验好，无需 VPN，内容实时同步  
**缺点**：Vercel Functions 有免费额度限制（100GB-小时/月，个人博客绰绰有余），需要写一个 API 路由  
**改动量**：中等（新增一个 `api/` 目录下的 serverless function，前端改调你自己的 API）

#### 方案二：构建时拉取（Build-time Fetching）

在 `vite build` 构建阶段，通过 Node.js 脚本把 GitHub 仓库所有 `.md` 文件拉取到本地，然后像本地模式一样用 `import.meta.glob` 加载。

```
构建时（Vite/Node.js）──→ api.github.com  ✅ 构建机通常不在墙内
                        └──→ raw.githubusercontent.com  ✅ 同上
                        
构建产物 = 静态 HTML + 内嵌文章内容（零运行时 API 调用）
```

**优点**：零运行时依赖，部署最简单，用户体验最好（文章直接内嵌在 JS bundle 中）  
**缺点**：文章更新需要重新构建部署（不过可以配合 GitHub Actions + Webhook 自动触发）  
**改动量**：小（写一个构建脚本 + 修改 loader 逻辑）

#### 方案三：GitHub 代理服务

直接使用社区已有的 GitHub 代理方案，比如 [vercel-github-proxy](https://github.com/goukey/vercel-github-proxy)，把 `raw.githubusercontent.com` 和 `api.github.com` 的请求转发到代理域名。

**优点**：改动最小（只改 URL）  
**缺点**：依赖第三方服务稳定性，Token 经过代理有安全风险，且代理也可能被墙

---

### 我的建议

**首推方案二（构建时拉取）**，原因：

1. **改动最小** — 你已有本地 `loader.ts` + `import.meta.glob` 的完整实现，构建时拉取只是把 GitHub 上的文件下载到 `content/posts/` 目录，然后走本地模式
2. **零运行时风险** — 不依赖 Vercel Functions 额度，不依赖任何第三方代理
3. **用户体验最佳** — 文章内容随静态资源一起通过 CDN 分发，秒开
4. **自动部署** — 配合 GitHub Actions，每次仓库 push 自动触发 Vercel 重新构建，实现"推送即更新"

报错很明确： TypeScript 6.0 废弃了 baseUrl 选项 。Cloudflare Pages 构建环境安装了 TS 6.0.3，而你本地可能是旧版本所以没报错。

修复很简单：删除 baseUrl ， paths 在 TS 5+ 中已经可以独立工作（相对于 tsconfig 所在目录解析

改动只有一行：删除 "baseUrl": "." 。

为什么这样改可行 ：TypeScript 5+ 中， paths 不依赖 baseUrl 也能独立工作—— "./src/*" 会相对于 tsconfig.app.json 所在目录（即项目根目录）解析，和之前的 @/* → src/* 映射完全一致，不影响 Vite 别名。

另外提醒一下：你的 package.json 里锁的是 "typescript": "6.0.3" ，本地 pnpm install 也会装 6.0。如果你本地 vue-tsc -b 没报错，可能是 node_modules 里还残留旧版本。建议本地也跑一次 pnpm install 确认。
