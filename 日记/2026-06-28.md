**在编写组件时，为了让它完美扮演“背景”的角色，给外层容器加了 `z-[-1]`（使它沉在页面最底层）。

在这种情况下，**浏览器的层级遮挡机制**会起作用：即使你页面上看起来什么都没有，你页面的根节点（比如 `#app` 或主布局容器）依然作为上层图层，把鼠标事件“拦截”掉了，导致底层的 Canvas 根本接收不到 `@mousemove` 事件。

### 核心解决方案

最稳妥、优雅的解决办法是：**将鼠标和触摸的事件监听器从 Canvas 标签上移除，直接绑定到全局的 `window` 对象上**。这样不论你的页面有多少图层、组件怎么嵌套，背景都能实时捕获到全屏的鼠标轨迹。

- **移除了 Canvas 上的行内事件绑定**：避免了模板里的事件因为 DOM 层级深浅而被遮挡。
    
- **在 `onMounted` 中增加了 `window.addEventListener`**：捕获全局的鼠标滑动。同时 Canvas 的样式中加入了 `pointer-events-none`，使其不影响你未来在背景之上放置点击按钮或链接。
    
- **在 `onBeforeUnmount` 中同步移除监听**：保证单页应用路由切换时，不会遗留全局事件导致报错。

在阅读源码前，你可以通过以下三个核心公式/逻辑来快速理解组件的底层行为：

- **物理朦胧感** = $50\%$ 低分辨率 Canvas 渲染 + CSS 硬件加速高斯模糊（`blur-[65px]`）。
    
- **丝滑交互（Lerp）** = $\text{当前坐标} = \text{当前坐标} + (\text{目标坐标} - \text{当前坐标}) \times 0.05$。
