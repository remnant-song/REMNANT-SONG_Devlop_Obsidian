## 设计方案

### 分类规则

```
src/content/posts/
├── tech/                    → 分类 "tech"
│   └── hello-tech.md        → slug "hello-tech"
├── life/                    → 分类 "life"
│   └── hello-life.md        → slug "hello-life"
└── standalone.md            → 分类 ""（根级），slug "standalone"
```

### 路由设计

| 路由 | 页面 | 说明 |
|---|---|---|
| `/blog` | BlogListView | 全部文章列表，按分类分组；可通过 `?category=tech` 过滤 |

| `/blog/:category/:slug` | BlogPostView | 分类下文章详情 |

不用 `/blog/:category` 作为分类过滤页（会和 `:slug` 冲突），改用 `?category=xxx` 查询参数。

### 排序

按文件名降序（字典序），如果文件以 `2026-08-09-` 开头则天然按时间倒序。

## 根因分析

我找到了问题的根本原因。问题出在 `loader.ts` 中存在**模块级副作用**导致 Vite 懒加载链路断裂。

### 调用链追溯

点击导航栏"博客"按钮时，整个执行链路如下：

```
1. 用户点击 <router-link to="/blog">
2. Vue Router 匹配路由，触发懒加载:
   () => import('@/views/blog/BlogListView.vue')
3. Vite dev server 返回 BlogListView.vue 模块
4. BlogListView.vue 的 <script setup> 开始执行
5. 遇到 import { loadAllPosts } from '@/utils/markdown/loader'
6. 浏览器向 Vite 请求 loader.ts 模块
7. loader.ts 执行模块级代码:
   const postModules = import.meta.glob('/src/content/posts/**/*.md', { eager: true })
8. ⚠️ 此处可能抛异常 / 返回空对象
```

核心问题在**第 7 步**：`import.meta.glob` 是 Vite 的编译时转换语法。在**全量刷新**时，Vite 会完整构建模块依赖图，把所有 `.md` 文件也一并编入依赖链，所以 `eager: true` 能正确返回包含所有文件的对象。

但在**客户端懒加载**时，Vite 的模块图是增量构建的。当 `loader.ts` 通过懒加载链首次进入模块图时，`import.meta.glob` 的 `.md` 子模块可能尚未被 Vite 的依赖分析器发现，导致：

- 返回**空对象 `{}`**，`loadAllPosts()` 返回空数组
- 或者更严重：**`import.meta.glob` 未被正确转换**，运行时抛出 `ReferenceError`，组件整个 setup 失败，`<router-view>` 区域空白

### 为什么刷新就好了？

全量刷新时，浏览器从零开始请求 `index.html` → 加载主入口 JS → Vite 自顶向下构建完整模块依赖图，此时 `import.meta.glob` 可以被正确展开。

### 证据指向

1. "只有 header 和 footer" → `<main>` 区域为空，说明 `BlogListView` 组件**根本没有渲染成功**（不是渲染了空列表）
2. 刷新后正常 → 模块在全量加载时能正确初始化
3. `DefaultLayout.vue` 使用了 `<transition mode="out-in">`：旧组件退出后，新组件若 setup 失败，`<main>` 就完全是空的

---

### 建议修复

将 `import.meta.glob` 从模块级常量改为**函数内懒初始化**，并加一层防御

---

## 总结

| 现象 | 原因 |
|---|---|
| 点击导航 → 白屏 | `loader.ts` 模块级 `import.meta.glob` 在懒加载链路中未被 Vite 正确展开，`BlogListView` 组件 setup 失败 |
| 刷新 → 正常 | 全量加载时 Vite 自顶向下构建完整模块依赖图，glob 被正确转换 |

**修复方案**（两处改动）：

1. **`loader.ts`**：将 `import.meta.glob` 从模块顶层常量改为 `getPostModules()` 函数内懒初始化，包裹 try-catch 防御，同时改用相对路径 `../../content/posts/**/*.md`（更符合 Vite 惯例）
2. **`loader.ts`**：`loadAllPosts()` 内部改为调用 `getPostModules()` 获取结果
