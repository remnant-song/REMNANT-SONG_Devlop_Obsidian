针对“Markdown 博客”这一核心模块，在原有个人网站整体定位下，将需求进一步细化为可执行的开发规划。以下内容仅关注博客功能本身，暂不涉及视觉风格系统、3D 等创意模块，但保留接入它们的扩展点。

一、博客模块需求细化

1. 内容来源与同步
1.1 博客文章统一存放于指定的 GitHub 公开仓库中，每篇文章为独立的 Markdown 文件。
1.2 文件命名建议采用 `YYYY-MM-DD-slug.md` 格式，或在 Markdown 头部通过 frontmatter 声明日期与别名。
1.3 文章支持 frontmatter 元数据，至少包含：标题、日期、标签（可多个）、摘要、是否草稿。可扩展自定义字段。
1.4 在网站构建阶段，自动从 GitHub 仓库拉取最新 Markdown 文件，无需手动导出或复制。
1.5 同步方式应兼顾开发预览时的即时性（本地可快速调试）与生产构建的可靠性。

2. 内容解析与渲染
2.1 Markdown 解析需支持标准语法：标题、段落、列表、链接、图片、代码块、表格、引用等。
2.2 代码块需有语法高亮，支持常见编程语言，并提供可选的显示行号、复制按钮。
2.3 支持在 Markdown 中内嵌 HTML，用于复杂排版或插入特殊组件。
2.4 图片路径可引用相对路径（相对于 Markdown 文件或仓库根目录）或外部 URL，构建时自动处理路径映射，确保页面正确显示。
2.5 允许在 Markdown 中通过特定语法插入自定义组件，如提示框、可折叠区块、音频播放器、乐谱占位符等，为后续特色内容预留接口（博客初期可仅保留接口，使用默认渲染）。
2.6 解析过程需处理 XSS 安全问题，对输出 HTML 进行安全过滤。

3. 页面结构与路由
3.1 博客整体作为一个独立板块，基础路由前缀建议为 `/blog`。
3.2 文章列表页：展示所有已发布文章，按日期倒序排列，每项显示标题、日期、摘要、标签。支持分页或无限滚动，初期可采用简单的“加载更多”或前 N 篇列表。
3.3 文章详情页：路由为 `/blog/[slug]` 或 `/blog/[year]/[month]/[slug]`，根据 frontmatter 的 slug 或文件名生成。详情页渲染完整的 Markdown 内容。
3.4 标签归类页：可查看某一标签下的文章列表，路由如 `/blog/tag/[tag]`。
3.5 归档页（可选）：按年份或月份分组的文章索引，路由 `/blog/archive`。
3.6 RSS/Atom 订阅源：生成标准格式的 Feed 文件，供 RSS 阅读器订阅，文件路径 `/blog/feed.xml` 或 `/rss.xml`。

4. 交互与体验
4.1 文章列表和详情页均需具备良好的加载性能，首屏文章列表应为静态生成内容，无需客户端实时请求。
4.2 文章内图片点击可放大查看（Lightbox），作为基础增强。
4.3 代码块需有横向滚动条以适配移动端窄屏，代码不折行破坏可读性。
4.4 文章详情页提供上一篇 / 下一篇导航。
4.5 页面可发现性：提供站点地图（sitemap.xml）中自动包含所有文章链接，SEO 友好的 title 与 meta description，自动生成 Open Graph 标签。

5. 管理与维护
5.1 发布新文章只需向 GitHub 仓库推送 Markdown 文件，网站通过重新构建即可更新，无需登录后台。
5.2 支持通过 Webhook 触发自动部署（如 Vercel 关联 Git 仓库后 Push 自动构建）。
5.3 对于非技术人员，应提供清晰的文档说明如何编辑和添加文章，包括 frontmatter 的写法、图片引用方式等。

6. 与整体网站的整合
6.1 博客页面的基础布局应与全站导航、页脚保持一致，但视觉风格可暂时使用一套基础样式，未来可被全局风格切换系统覆盖。
6.2 博客模块的样式应使用全站统一的设计令牌（颜色、字体等 CSS 变量），确保将来切换风格时无需修改博客内部代码。
6.3 博客文章详情页内部由 Markdown 生成的 HTML 结构，需预留样式钩子（class 命名约定），方便不同风格下定制排版。

二、开发任务拆解

以下任务按实现顺序排列，每一项均可作为独立的可交付增量。

第零阶段：项目工程准备

任务 0.1：初始化 Vue3 + Vite 项目，集成所需基础依赖（Vue Router、Pinia）。
任务 0.2：配置 Tailwind CSS 并搭建基础的全局布局组件（Header、Footer、通用容器）。
任务 0.3：规划目录结构，明确博客相关模块的存放位置（如 `src/pages/blog/`、`src/utils/markdown/`、`src/composables/` 等）。
任务 0.4：建立 GitHub 仓库用于存放 Markdown 文章，初始化第一篇示例文章，包含完整 frontmatter。

第一阶段：内容获取与处理

任务 1.1：实现开发环境下的文章读取方案，在 Vite 中可通过 `import.meta.glob` 直接加载本地文章目录（本地调试时克隆文章仓库或使用本地路径映射）。
任务 1.2：实现生产构建时的文章获取逻辑，编写脚本在构建前从 GitHub API 或通过 git clone 浅层拉取文章仓库，保存到指定目录。
任务 1.3：设计 frontmatter 解析函数，提取标题、日期、标签、摘要、slug、草稿状态等，解析出错时有容错处理。
任务 1.4：实现文章排序、过滤（草稿、未来日期）与标签聚合的数据处理层，生成文章列表、标签映射等静态数据。

第二阶段：Markdown 渲染与增强

任务 2.1：集成 Markdown 解析器（如 markdown-it），配置基础选项，扩展插件支持代码高亮（如 highlight.js 或 Shiki）。
任务 2.2：自定义 Markdown 渲染输出，为标题添加锚点链接，为代码块添加复制按钮和语言标注，为图片添加 Lightbox 触发的 class。
任务 2.3：实现图片路径转换逻辑，将 Markdown 中的相对路径转译为构建后的正确资源路径（如图片可放于文章同级 assets 目录，构建时拷贝到 public 下）。
任务 2.4：创建可扩展的自定义组件注入机制，先实现一个 `::note` 容器指令的解析，将其转换为特定样式的提示框 HTML。
任务 2.5：对 Markdown 渲染出的 HTML 进行安全清理，过滤危险标签和属性。

第三阶段：博客页面与路由

任务 3.1：配置 Vue Router 博客相关路由：文章列表、文章详情、标签列表、标签过滤、归档页（如需要）。
任务 3.2：开发文章列表页组件，展示所有文章摘要卡片，实现分页（或加载更多），处理空状态。
任务 3.3：开发文章详情页组件，接收 slug 参数，匹配文章数据，渲染 Markdown 内容。处理 404 状态。
任务 3.4：实现上一篇 / 下一篇文章的导航逻辑。
任务 3.5：开发标签相关页面，包括标签列表页（显示所有标签及对应文章数）和标签筛选页（展示该标签下的文章列表）。
任务 3.6：实现 RSS Feed 生成，在构建时产生静态 XML 文件。
任务 3.7：确保所有博客页面生成合适的 SEO 元信息（使用 vue-meta 或 @vueuse/head）。
任务 3.8：添加基本交互细节：代码块一键复制、图片点击 Lightbox 弹窗。

第四阶段：与 GitHub 同步及自动化

任务 4.1：编写构建脚本，在 `vite build` 前执行文章同步任务（如调用 GitHub API 下载最新文件），并处理错误情况（如网络不通时使用缓存）。
任务 4.2：配置 Vercel 部署，关联主项目仓库，设置构建命令与环境变量（GitHub Token 等）。确保每次主仓库 push 时自动构建并部署。
任务 4.3：如果使用单独的文章仓库，在文章仓库中设置 Webhook 或利用 Vercel 的 Deploy Hooks，在文章更新时触发主站重新构建。
任务 4.4：实现构建缓存机制，避免每次构建都重新下载未改动的文章。

第五阶段：样式适配与风格准备

任务 5.1：为博客模块编写基础样式，使用 Tailwind 的排版插件（如 @tailwindcss/typography）快速美化文章正文排版。
任务 5.2：抽象设计令牌（CSS 变量）用于文章页的颜色、字体、间距等，确保未来风格切换时可覆盖这些变量。
任务 5.3：处理响应式，保证文章列表、详情页在移动端显示良好，图片和代码块不溢出。

第六阶段：文档与开发者体验

任务 6.1：编写博客使用文档，指导如何添加文章、填写 frontmatter、管理图片等，放在网站内或项目 README 中。
任务 6.2：添加本地开发说明，包括如何克隆文章仓库到本地进行预览。
任务 6.3：可选：配置 ESLint 与 Prettier，保证代码风格一致。
